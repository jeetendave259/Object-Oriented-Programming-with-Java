Topic 1

How Java Evolved

Programming languages evolve as hardware, software, and the problems people need to solve change. Java brought familiar C-family syntax together with managed execution and a portable runtime.
A simplified language timeline

→
Java
managed, portable bytecode

C became influential for systems work because it offered structured code while still allowing close control of resources. C++ added object-oriented features and retained much of the C-family style. Java drew on that syntax and on object-oriented ideas, but introduced a virtual machine so compiled programs could target a common runtime instead of a specific processor instruction set.

The growth of the Internet increased the value of programs that could be distributed and run on different kinds of computers. Java bytecode and the Java Virtual Machine (JVM) address this by separating compilation from the details of the host processor. Java has since been used for desktop, server, web, embedded, and mobile software.

Java began in 1991 at Sun Microsystems as part of the Green Project, led by James Gosling and colleagues. The team first targeted software for consumer electronic and embedded devices; the language was initially called Oak. The rapid expansion of the World Wide Web made portable, downloadable programs especially compelling, and Oak was renamed Java before its public release in 1995. Java's Internet success was a later opportunity, not the original reason the project began.

Language lineage: C and C++ influenced Java's familiar syntax, but Java is its own language—not a direct upgrade or replacement for C++.

Procedural and Object-Oriented Ways to Organize Code

Java is class-based and strongly supports object-oriented programming, while still including primitive values and static methods for other programming styles.

“Write once, run anywhere” means compatible bytecode can run on different platforms when an appropriate JVM and libraries are available; it does not mean every program is free of platform-specific behavior. In current Java distributions the JDK normally includes everything needed to run Java code, so a separate JRE download is not always provided.

A Simplified View of JVM Internals

Class loading and verificationFinds class files, links types, and checks bytecode before execution.
Runtime memoryThe heap stores objects; each thread has a call stack and execution state.
Execution engineInterprets bytecode and may use just-in-time compilation for frequently used code.
  • Heap: shared runtime area where objects and arrays are allocated; garbage collection can reclaim unreachable objects.
  • JVM stack: each thread has its own stack of method frames, including local variables and intermediate results.
  • Program counter: each thread tracks the current bytecode instruction it is executing.
  • Class metadata: the JVM keeps loaded class information in a runtime method area; implementations may organize this storage differently.
  • Native support: native method stacks and the Java Native Interface (JNI) support calls between Java and platform-specific native libraries.

The JVM also coordinates garbage collection for eligible objects and can communicate with native code through defined interfaces. Java manages memory automatically, but programs still need to close external resources such as files and network connections.

Common Java Platform Families

  • Java SE: Core language, standard libraries, and general-purpose applications.
  • Jakarta EE: Enterprise application specifications and APIs built on Java SE; older material may call this Java EE.
  • Java ME: A platform family designed for constrained and embedded environments.

Features and Design Goals

  • Portable: Bytecode targets a JVM rather than a single processor architecture.
  • Object-oriented: Classes and objects support encapsulation, reuse, and polymorphism.
  • Managed and robust: Type checking, exceptions, and automatic memory management help detect or contain common faults.
  • Concurrent: The language and standard libraries provide thread and concurrency tools.
  • Network-capable: Libraries support communication across processes and networks.
  • Performance-aware: JVM implementations can optimize frequently executed code at runtime.
Remember: Java is compiled and also executed by a runtime. Source code becomes bytecode; a JVM interprets or compiles that bytecode for its host platform.

Comments, Identifiers, and Keywords

  • Identifiers name classes, variables, and methods. They are case-sensitive, cannot contain spaces, and cannot be reserved keywords.
  • Names may begin with a letter, underscore, or dollar sign; conventional Java style uses UpperCamelCase for types and lowerCamelCase for methods and variables.
  • // begins a line comment; /* ... */ encloses a block comment; /** ... */ is a documentation comment.
  • Keywords such as class, if, return, and static have language-defined meanings and cannot be used as identifiers.
Access-modifier note: public, protected, and private control access; when no modifier is written, package access applies. Modifiers belong to declarations, not to the same category as keywords that define control flow.
Topic 4

Data Types, Variables, and Conversions

A variable is a named storage location with a declared type. Java checks the type of a value when it is declared, assigned, passed, or returned.
Primitive
Stores a value directly, such as an integer, decimal, character, or boolean.
Reference
Stores a reference to an object, array, or string. A reference may also be null.

Identifier Rules

  • An identifier may use letters, digits, underscores, and dollar signs, but cannot begin with a digit or contain whitespace.
  • Identifiers are case-sensitive: total and Total are different names.
  • Reserved keywords cannot be used as identifiers. Choose descriptive names and follow Java naming conventions.
  • Local variables must be definitely assigned before use; final variables can be assigned only once.

Widening and Narrowing

A widening conversion moves to a type that can represent the source type's full range in that conversion context, such as int to long. A narrowing conversion may lose information and generally requires an explicit cast.

Topic 7

Arrays

An array stores a fixed-length sequence of values of one declared component type. Its index begins at zero, and its length is available from the array's length field.
int[] marks;                 // declare a reference
marks = new int[3];          // create a three-element array
marks[0] = 90;               // first element
int[] values = {4, 8, 12};   // declare, create, and initialize

New numeric arrays start with zero values, char arrays with the null character, boolean arrays with false, and reference arrays with null. Accessing an index outside 0 through length - 1 causes an ArrayIndexOutOfBoundsException.

StringBuilder and StringBuffer

Repeated concatenation in a loop can create many temporary strings. A mutable text builder supports operations such as append, insert, replace, delete, and reverse. StringBuilder is generally preferred for single-threaded work; StringBuffer provides synchronized methods for legacy thread-safe use.

Both expose length() and capacity(). Capacity is the space available before a resize is required; it is not the number of characters currently present.
